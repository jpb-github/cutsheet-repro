# Cutsheet PDF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task by task; steps use checkbox syntax. Way of working of this project: each task is detailed just before it is executed (the Files, Interfaces and Tests below are fixed, the steps are refined then), tested with its own tests only, marked done here. Commit and push only when the user asks.

**Goal:** from the Drawer Blocks tab, a Cutsheet button that packs the pieces on MDF sheets with guillotine (edge to edge) cuts, in 15 s by default on up to 80 % of the cores, and writes a PDF (summary, one page per sheet with numbered cuts, kerf and pocket screw marks, one page per distinct piece with dimensions); a Refine button searches further.

**Architecture:** `core/cutting.py` (packer, search, cut order; standard library only), `core/cutsheet.py` (labels, pocket screw positions, cut instructions, the data the PDF shows), `app/cutsheet_pdf.py` (Qt `QPdfWriter` painting), `app/cutsheet_flow.py` (background search, save, open); the form gets grouped one-letter lines.

**Tech Stack:** Python 3.14, PySide6 (QPdfWriter, QtPdf for tests), `concurrent.futures` process pool, pytest.

**Spec:** `docs/superpowers/specs/2026-11-13-cutsheet-design.md` (and the drawer blocks spec it builds on).

## Global Constraints

- `core/` imports only the standard library and never `app/`. The PDF is written with Qt, no new dependency.
- All dimensions in mm. Defaults: sheet 2400 x 1200 for both thicknesses, kerf 5, search 15 s, workers = max(1, floor(0.8 x cpu count)), A4 landscape.
- Every cut crosses the whole rectangle it divides; pieces may be rotated by 90 degrees; no trim of the sheet edges; a sheet holds one material only.
- Default form result: 1 thick sheet and 1 thin sheet, every piece placed exactly once. With 1200 x 1200 sheets: 2 thick sheets.
- Pocket screw marks: i + 0.5 over n times the joint edge length (the counts of `per_joint`); both short ends of "Drawer front and back", both long edges of "Box side".
- Tests with a time budget are forbidden: use `iterations=` and a seed so that results are reproducible.

## Review Focus

- A piece that is exactly the sheet, or exactly fills a free rectangle: no cut is made, no negative rectangle appears.
- The leftover beside a piece is narrower than the kerf: it is waste, the cut still happens, nothing negative.
- Twenty identical pieces, one piece, and a piece that fits only when rotated.
- Cancel before the search found anything better than the first run: the first (synchronous) result is still returned.
- One CPU core (workers = 1) and a machine where the process pool cannot start: fall back to running in the calling process.
- The PDF is open in a viewer (file locked): error reported, another name offered, nothing half written.
- A drawer so short that two pocket screws at i + 0.5 over n are closer than the screw heads allow: still positioned, never outside the piece.

## File Structure

- Create `core/cutting.py`, `core/cutsheet.py`, `app/cutsheet_pdf.py`, `app/cutsheet_flow.py`, tests `tests/test_cutting.py`, `tests/test_cutsheet.py`, `tests/test_cutsheet_pdf.py`, `tests/test_cutsheet_flow.py`.
- Modify `core/params.py` (`Param.row`, `Param.short`), `core/catalogue.py` (new parameters, sheet check), `app/param_form.py` (grouped lines), `app/drawer_blocks_tab.py` (no View button, Cutsheet and Refine), `app/main_window.py` (wiring, busy state), `tests/test_drawer_blocks_*.py`, `tests/test_params.py`.

- [x] **4. Search, refine, cores** (done in `core/cutting.py`, tests in `tests/test_cutting_search.py`; candidates `variant_for(index, seed)`: indices 0..31 are every fixed select/split combination with order area or long, then random ones from the seed; candidate 0 runs in the calling process; batches of 16 per worker; a piece set that does not fit one sheet is spread over several, the score counts sheets first)
  - Files: `core/cutting.py`, tests.
  - Interfaces: `Solution(layouts: tuple[SheetLayout, ...], score: tuple)`; `score(layouts) -> tuple` = (number of sheets, wasted area, number of cuts, minus the largest offcut); `optimize(items, sheet, kerf, *, seconds: float = 15.0, iterations: int | None = None, workers: int | None = None, seed: int = 0, start: Solution | None = None, on_progress: Callable[[Solution], None] | None = None, cancel: Callable[[], bool] | None = None) -> Solution` (the first deterministic run is done in the calling process so there is always a result; the rest in a `ProcessPoolExecutor` of `workers` processes, default `default_workers()` = max(1, floor(0.8 x cpu count)); falls back to the calling process when the pool cannot start or workers = 1; `iterations` replaces the clock; `start` is the incumbent, the result is never worse than it; `on_progress` is called with each better solution; `cancel()` is polled between batches).
